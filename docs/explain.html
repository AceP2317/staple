Purpose

Staple plans a repair fleet's next day. It decides who takes each call, what each truck carries, and what people do before 08:00, so more repairs finish on the first visit.

Key points

  • Every call, technician, part and dollar is invented. The method is real, and nothing here shows the gain on a real fleet.
  • It is scored as a back-test. Each method learns from the earlier days, then plans the last 92 days unseen.
  • Over those days Staple beats the current rules on all 5 measures in the scorecard.
  • Every gain sits beside a control, which is the method run again with one link in its data broken.
  • Claude codes every booking from the customer's own words. Staple plans the trucks, and people act before 08:00.

Methods page
Every formula, prompt, query and check.

Written in Python, SQL and JavaScript: 17 Python files invent the history, predict parts, load trucks, ask Claude, replay dispatch, write these pages and check it all; 16 SQL files hold the tables and the 15 metric queries; 2 JavaScript files run the hints and switches. Beside them, 8 Bash scripts run the checks before each commit, and 4 HTML files and 1 CSS file lay out the pages. Nothing is installed beyond Python. Every figure in the evidence comes from the queries in sql/metrics/, and the plan is the record the dispatch replay kept.
